# @oxth/nestjs-otel — Plan 1: Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A publishable `@oxth/nestjs-otel` that gives a NestJS 11/12 app traces, metrics, and logs over OTLP from one bootstrap line plus `OtelModule.forRoot()`. It covers HTTP (Express and Fastify), `Class.method` spans, Sentry-style error capture, redacted request bodies on failed requests, and trace-correlated logs.

**Architecture:** There are two layers.
- **`register` entry:** starts `NodeSDK` before the app loads (exporters configured from standard `OTEL_*` env vars; auto-detected instrumentations; an ESM loader hook). The SDK handle lives on `globalThis`, so the CJS and ESM copies of the package share it.
- **`OtelModule`:** the NestJS-aware layer. A factory provider patches controller, provider, and guard **prototypes** while DI instantiates them, which is before `app.init()` binds routes. A global interceptor adds route names and failure context to the HTTP root span. A logger, `TraceService`, and `MetricService` complete it.

**Tech Stack:** TypeScript 5, pnpm, tsdown (dual CJS/ESM build), Vitest 5, `@opentelemetry/sdk-node` 0.300.x, `@opentelemetry/api` 1.x, `@opentelemetry/api-logs`, `@opentelemetry/instrumentation-http`, `-express`, `@fastify/otel`, `-pino`, `-runtime-node`, NestJS 11/12, rxjs 7.

**Spec:** `docs/superpowers/specs/2026-10-28-nestjs-otel-design.md`

## Global Constraints

- Package name `@oxth/nestjs-otel`. Entry points: `.`, `./register`, `./pino`. Each ships ESM (`.mjs`), CJS (`.cjs`), and `.d.ts`/`.d.mts` types.
- `engines.node`: `>=22.15.0`. The spec says ≥ 22; it's raised because `@opentelemetry/sdk-node@0.300` requires `>=22.15.0`.
- Peer dependencies: `@nestjs/common` and `@nestjs/core` `^11.0.0 || ^12.0.0`, `rxjs ^7.8.0`, `reflect-metadata ^0.2.0`, `@opentelemetry/api ^1.9.0`. Optional peers: `pino`, `nestjs-pino`, `@nestjs/platform-express`, `@nestjs/platform-fastify`.
- Instrumentation scope name for the tracer, meter, and logger: `@oxth/nestjs-otel`.
- Config comes only from standard env vars (`OTEL_SERVICE_NAME`, `OTEL_EXPORTER_OTLP_*`, `OTEL_TRACES_EXPORTER`, `OTEL_METRICS_EXPORTER`, `OTEL_LOGS_EXPORTER`, `OTEL_SDK_DISABLED`, `OTEL_PROPAGATORS`, `OTEL_NODE_ENABLED_INSTRUMENTATIONS`, `OTEL_NODE_DISABLED_INSTRUMENTATIONS`). Plan 1 adds **no** `OXTH_*` variables.
- Default OTLP protocol: `http/protobuf`.
- Redaction censor string: `[REDACTED]`. Default body limit: `8192` bytes.
- **Telemetry code never throws into app code.** Every hook and wrapper catches its own internal errors and reports them through `diag`. Exceptions thrown by user code are always re-thrown unchanged.
- No `instrumentation-nestjs-core`. The library's own wrappers produce the Nest spans (spec §9 left this to the builder; this avoids duplicate spans).
- Span attributes for wrapped methods: `code.namespace` = class name, `code.function` = method name (spec §5.2). Span name: `ClassName.methodName`.

## Review Focus

1. **Route and DI metadata after wrapping:** `@Get`, `@HttpCode`, `@UseGuards`, `@MessagePattern`, and parameter decorators must still work on wrapped methods (metadata copied to the wrapper). Test: Task 6, `keeps routing, guards and HttpCode after wrapping`.
2. **Signal handling:** SIGTERM with no other listener must still exit the process (with exported data flushed). With `app.enableShutdownHooks()`, Nest's hooks must still run exactly once. Test: Task 4, `sigterm exits when only our listener exists` and `nest shutdown hooks still run`.
3. **Two copies of the package:** a CJS app launched with `--import` loads the ESM `register` while the app `require`s the CJS index. The module must still find the SDK and must not warn "register not loaded". Test: Task 5, `cjs app with --import shares sdk state`.
4. **Collector down or unreachable:** the app keeps serving, there's no unhandled rejection, and stderr gets at most one exporter warning per 60 s. Test: Task 4, `exporter failures are rate limited`.
5. **Hostile request bodies:** circular references, depth > 20, 100k-element arrays, `Buffer`, `BigInt`, a throwing `toJSON`, and multibyte truncation must never throw and must produce valid UTF-8. Test: Task 2, `redact survives hostile input` and `truncates on utf-8 boundary`.

### Task 2: Redactor and body serialization

**Files:**
- Create: `src/redact/defaults.ts`, `src/redact/redactor.ts`
- Test: `test/unit/redactor.test.ts`

**Interfaces:**
- Produces:
```ts
export interface RedactOptions {
  keys?: string[];                 // added to defaults
  replaceDefaultKeys?: boolean;    // default false
  patterns?: RegExp[];             // value patterns, added to defaults
  replaceDefaultPatterns?: boolean;
  censor?: string;                 // default CENSOR
  custom?: (value: unknown, path: readonly string[]) => unknown; // runs after built-in, per leaf
}
export interface Redactor {
  redact(value: unknown): unknown;            // deep copy, never mutates input, never throws
  redactString(value: string): string;        // applies value patterns
  isSensitiveKey(key: string): boolean;
  redactHeaders(h: Record<string, string | string[] | undefined>): Record<string, string | string[] | undefined>;
}
export function createRedactor(opts?: RedactOptions): Redactor;
export function serializeBody(value: unknown, maxBytes: number): { body: string; truncated: boolean };
```

**Decisions (the spec leaves these open):**
- **Key normalization:** lowercase, then strip `-` and `_`.
- **Substring keys** (match if the normalized key *contains* one): `password`, `passwd`, `secret`, `token`, `authorization`, `apikey`, `cookie`, `session`, `creditcard`, `cardnumber`, `cvv`, `ssn`, `privatekey`.
- **Exact-match key:** `auth`. Matching it as a substring would redact `author`. **Plan's call**, a small deviation from the spec's "key substring".
- **Default value patterns:** JWT `/eyJ[\w-]+\.[\w-]+\.[\w-]+/g` and Bearer `/Bearer\s+[\w\-.~+/]+=*/gi`. Card numbers are left out (too many false positives). **Plan's call.**
- **Default headers:** `authorization`, `cookie`, `set-cookie`, `x-api-key`, plus anything `isSensitiveKey` matches.
- **Limits:** max depth 20; deeper values become `'[Truncated]'`. Arrays capped at 1000 items, then `'[… N more]'`. Circular references become `'[Circular]'`.
- **Value handling:** a `Buffer` becomes `'[Buffer N bytes]'`, a `bigint` becomes its string, a `Date` becomes its ISO string, a throwing getter or `toJSON` becomes `'[Unserializable]'`. Functions and symbols are dropped.
- **Truncation:** `serializeBody` uses `JSON.stringify` on the already-redacted value. If the UTF-8 byte length exceeds `maxBytes`, it cuts at the last whole code point at or under `maxBytes` (no broken surrogates or partial UTF-8).

### Task 3: Error classification and recording

**Files:**
- Create: `src/errors/classify.ts`, `src/errors/record.ts`
- Test: `test/unit/errors.test.ts`

**Interfaces:**
- Consumes: `@opentelemetry/api` `Span`, `SpanStatusCode`.
- Produces:
```ts
export interface ClassifyOptions { treat4xxAsError: boolean }
export function classifyError(err: unknown, opts: ClassifyOptions): { isError: boolean; httpStatus?: number };
export function formatStack(err: unknown): string;       // stack + "\nCaused by: " chain, max depth 5, cycle-safe
export function recordError(span: Span, err: unknown, opts: ClassifyOptions): void;
export function hasStackRecorded(span: Span, stack: string): boolean;  // used by OtelLogger (Task 10)
export function markStackRecorded(span: Span, stack: string): void;
```

**Behavior:**
- **HTTP status detection:** an error is treated as an HTTP error if it's an instance of `HttpException`, *or* it has a `getStatus(): number` method (duck typing, in case two copies of `@nestjs/common` are installed).
- **Classification:** status < 500 and `!treat4xxAsError` → `isError: false`. Everything else (non-HTTP errors, `RpcException`, strings, `undefined`) → `isError: true`.
- **`recordError` on an expected (4xx) error:** adds the span event `exception.handled` with `exception.type`, `exception.message`, `http.response.status_code`, and sets the attribute `error.expected=true`. Status stays unset.
- **`recordError` on an error:** the first time a given error *object* is recorded (tracked in a module-level `WeakSet`), it adds the event `exception` with `exception.type` (the constructor name), `exception.message`, and `exception.stacktrace` (from `formatStack`), and calls `markStackRecorded`. Every call sets status `{ code: ERROR, message }`. Primitive throws (not objects) are always recorded as events.

- Produces:
```ts
export type InstrumentationName = 'http' | 'express' | 'fastify' | 'pino' | 'runtime-node';
export interface BootstrapConfig {
  disabled: boolean;                               // OTEL_SDK_DISABLED === 'true'
  enabled: Set<string> | null;                     // OTEL_NODE_ENABLED_INSTRUMENTATIONS (null = all)
  disabledInstrumentations: Set<string>;           // OTEL_NODE_DISABLED_INSTRUMENTATIONS
}
export function readBootstrapConfig(env: NodeJS.ProcessEnv): BootstrapConfig;
export function isInstalled(pkg: string, fromDir?: string): boolean;   // createRequire(join(fromDir ?? process.cwd(), 'noop.js')).resolve(pkg)
export function buildResourceAttributes(env: NodeJS.ProcessEnv, cwd: string): Attributes;
export interface InstrumentationEntry { name: InstrumentationName; pkg: string | null; create(): Instrumentation }
export const INSTRUMENTATIONS: InstrumentationEntry[];   // Plans 2–4 append entries here
export function buildInstrumentations(cfg: BootstrapConfig, installed?: (pkg: string) => boolean): Instrumentation[];
export interface SdkOverrides { spanProcessors?: SpanProcessor[]; metricReaders?: MetricReader[]; logRecordProcessors?: LogRecordProcessor[] }
export function startSdk(cfg: BootstrapConfig, overrides?: SdkOverrides): SdkHandle | undefined; // undefined when disabled; idempotent
export function getSdkHandle(): SdkHandle | undefined;
```

**Behavior:**
- **Resource attributes:**
  - `service.name`: `OTEL_SERVICE_NAME`, falling back to the `name` field of `package.json` in the cwd. The fallback is **the plan's call**: it keeps setup to zero config. When the env var is set, NodeSDK's own env detector wins.
  - `service.version`: from `package.json` `version`, unless `OTEL_RESOURCE_ATTRIBUTES` contains `service.version`.
  - `deployment.environment.name`: from `NODE_ENV`, unless `OTEL_RESOURCE_ATTRIBUTES` sets it.
  - A missing or invalid `package.json` is not an error; those attributes are simply left out.
- **Instrumentation registry:**
  - `http`: `pkg: null`, always available. `requestHook(span, req)` sets `req[ROOT_SPAN] = span` for incoming requests.
  - `express`: `pkg: 'express'`.
  - `fastify`: `pkg: 'fastify'`, created with `new FastifyOtelInstrumentation({ registerOnInitialization: true })`.

**Defaults:**
- `controllers` and `providers`: true. `guards`, `interceptors`, and `pipes`: false.

**`instrumentApplication` rules:**
- **Runs from a factory provider** (`OTEL_INSTRUMENTED`) inside `OtelModule`, injecting `ModulesContainer` and `OTEL_OPTIONS`. Factory providers run while `NestFactory.create` instantiates the app, which is before `app.init()` registers routes. Patching **prototypes** therefore takes effect even for controllers the router binds later.
- **Candidates:** for each module, every wrapper in `controllers`, `providers`, and `injectables` whose `metatype` is a class (`typeof === 'function'` and has a `prototype`) and that is not a factory or value provider (`!wrapper.inject` and `!wrapper.isFactory`, or the equivalent fields in the installed Nest version).
- **Skipped modules:**
  - Nest internals: `InternalCoreModule`, and `OtelModule` itself.
  - **Dynamic modules** (`forRoot()`/`register()` style). These are almost always library modules (TypeORM, Bull, Config, Logger). **The plan's call** for the spec's "providers from node_modules are not traced", since a class's file of origin can't be known in ESM.
  - **Exceptions to both skips:** a class marked `@Trace()`, or one matching `include`, is always wrapped. A class matching `exclude` or marked `@NoTrace()` is never wrapped.
  - Detecting a dynamic module: the implementer looks up how the installed Nest exposes it (for example, the module token carrying dynamic metadata in `NestContainer`). The test pins the result.
- **Kind:**
  - Controllers wrap when `controllers` is on.
  - Providers wrap when `providers` is on, except guards, interceptors, and pipes (classes with `canActivate`, `intercept`, or `transform`), which follow their own flags.
  - **Guards always** get `wrapForErrorRecording` on `canActivate`, even when `guards` is off. The handler sends the error to `applyFailureContext` using the HTTP request taken from args[0] (the `ExecutionContext`).
- **Methods:** own prototype methods only (`Object.getOwnPropertyNames(proto)`), skipping:
  - `constructor`, getters and setters, non-functions, and already-wrapped methods
  - methods marked `@NoTrace()`
  - Nest lifecycle hooks: `onModuleInit`, `onApplicationBootstrap`, `onModuleDestroy`, `beforeApplicationShutdown`, `onApplicationShutdown`
- **Inherited methods:** walk up the prototype chain until `Object.prototype`, but wrap each method only once, at the most-derived class that defines it.
- **Span:** name `${Class}.${method}`, attributes `code.namespace` and `code.function`, plus any `SPAN_ATTR_META` parameter attributes.

**`OtelModule`:**
- `global: true`. Providers: `OTEL_OPTIONS`, `OTEL_INSTRUMENTED`, `TraceService`, `MetricService` (Task 11), `OtelLogger` (Task 10), and `{ provide: APP_INTERCEPTOR, useClass: HttpOtelInterceptor }` (Task 8). Exports: `TraceService`, `MetricService`, `OtelLogger`.

- Create: `src/http/route.ts`, `src/http/failure-context.ts`, `src/http/no-capture-body.decorator.ts`, `src/http/http-otel.interceptor.ts`
- Modify: `src/module/otel.module.ts` (register `APP_INTERCEPTOR`), `src/module/auto-instrument.ts` (guard error → `applyFailureContext`), `src/index.ts` (export `NoCaptureBody`)
- Test: `test/unit/route.test.ts`, `test/integration/failure-context.test.ts`, `test/e2e/http.e2e.test.ts`

**Interfaces:**
- Consumes: `ROOT_SPAN`, `recordError`, `classifyError`, `serializeBody`, `ResolvedOtelOptions`, `getRPCMetadata`/`RPCType` from `@opentelemetry/core`.
- Produces:
```ts
export function resolveRoute(req: any): string | undefined;   // express: (req.baseUrl ?? '') + req.route.path; fastify: req.routeOptions?.url ?? req.routerPath
export function getRootSpan(req: any): Span | undefined;       // req[ROOT_SPAN] ?? req.raw?.[ROOT_SPAN] ?? trace.getActiveSpan()
export const NO_CAPTURE_BODY_META = '@oxth/nestjs-otel:no-capture-body';
export function NoCaptureBody(): ClassDecorator & MethodDecorator;
export function applyFailureContext(req: any, err: unknown, o: ResolvedOtelOptions, flags?: { noCaptureBody?: boolean }): void;
@Injectable() export class HttpOtelInterceptor implements NestInterceptor { constructor(@Inject(OTEL_OPTIONS) o: ResolvedOtelOptions, reflector: Reflector) }
```

**Interceptor behavior** (HTTP context only; other context types pass straight through):
- **Route naming, before the handler:** `route = resolveRoute(req)`. If `route` is set:
  - `getRPCMetadata(context.active())`, when it is `RPCType.HTTP`, gets `.route = route`. This is what gives `http.server.request.duration` its `http.route` attribute.
  - `root.updateName(\`${req.method} ${route}\`)` and `root.setAttribute('http.route', route)`.
- **On error,** with `catchError(err => { applyFailureContext(req, err, o, { noCaptureBody }); throw err; })`. `noCaptureBody` comes from `NO_CAPTURE_BODY_META` on the handler or class, read with `reflector.getAllAndOverride`.
- **Response body:** only when `capture.responseBody` is on. Wrap `res.json`/`res.send` (Express) or `reply.send` (Fastify) for this one request, and when the status is ≥ 500 put the redacted, serialized payload on `http.response.body` (with `http.response.body.truncated` when it applies).

**`applyFailureContext(req, err, o)`:**
- `root = getRootSpan(req)`; if there is none, return. `{ isError } = classifyError(err, o.classify)`, then `recordError(root, err, o.classify)`, which adds the event only if no inner span already did (dedupe from Task 3). If `!isError`, return.
- `user.id` = `String(o.capture.getUserId(req))` when it's defined.
- **Body,** if `o.capture.requestBody && !noCaptureBody`:
  - `content-type` includes `application/json` or `application/x-www-form-urlencoded`, and `req.body !== undefined`: set `http.request.body` = `serializeBody(o.redactor.redact(req.body), o.capture.maxBodyBytes).body`, and set `http.request.body.truncated = true` only when the body was truncated.
  - Any other content type: set only `http.request.body.size` (from `content-length`) and `http.request.header.content-type`.
- Each attribute is set at most once per span (guard with a `WeakSet<Span>`), because the guard path and the interceptor path can both fire.

**Interfaces:**
- Consumes: `recordError`, `getSdkHandle`, `logs` from `@opentelemetry/api-logs`, `SCOPE_NAME`.
- Produces: `export function installProcessErrorMonitor(): void`. It is idempotent.

**Behavior:**
- Uses `process.on('uncaughtExceptionMonitor', (err, origin) => …)` **only**. It never adds `uncaughtException` or `unhandledRejection` listeners, so Node's default crash behavior stays the same.
- If there's an active span: `recordError(span, err, { treat4xxAsError: false })` and `span.end()`. The span is ended because the process is dying.
- Always emits a log record: severity `FATAL`, body = message, attributes `exception.type`, `exception.message`, `exception.stacktrace`, `process.uncaught.origin` = origin.
- Then calls `void getSdkHandle()?.forceFlush()` (best effort).

**Interfaces:**
- Consumes: `hasStackRecorded`, `markStackRecorded`, `SCOPE_NAME`.
- Produces:
```ts
export function toSeverity(level: LogLevel): { severityNumber: SeverityNumber; severityText: string };
// fatal→FATAL(21) error→ERROR(17) warn→WARN(13) log→INFO(9) debug→DEBUG(5) verbose→TRACE(1)
export interface OtelLoggerOptions extends ConsoleLoggerOptions { console?: boolean /* default true */; otlp?: boolean /* default true */ }
@Injectable() export class OtelLogger extends ConsoleLogger { constructor(context?: string, options?: OtelLoggerOptions) }
export function otelPinoMixin(): () => Record<string, string>; // { trace_id, span_id, trace_flags } from the active span, {} when none
```

**`OtelLogger` behavior:**
- For each level method (`log`, `error`, `warn`, `debug`, `verbose`, `fatal`), and only when `isLevelEnabled(level)`:
  - **OTLP** (`otlp: true`): emit a record with `logs.getLogger(SCOPE_NAME).emit({ severityNumber, severityText, body: <message as string; objects JSON.stringify'd>, attributes: { 'nest.context': context }, context: context.active() })`.
  - **Console** (`console: true`): keep Nest's usual console output, with ` trace_id=<32hex> span_id=<16hex>` appended to the line when a span is active. The implementer picks the `ConsoleLogger` override point that does this (for example `formatMessage`); the test pins the output.
- **`error(message, stack?, context?)`** while a span is active: if `stack` is a string and `!hasStackRecorded(span, stack)`, add the event `exception` with `exception.message` = message and `exception.stacktrace` = stack, set status ERROR, then call `markStackRecorded`. This dedupes against Nest's `ExceptionsHandler` logging an error that was already recorded.

**Pino:** the `pino` instrumentation from Task 4 already injects `trace_id`/`span_id` and sends logs over OTLP. `otelPinoMixin` is a manual fallback for setups where the instrumentation can't patch pino; the README documents it as such.
